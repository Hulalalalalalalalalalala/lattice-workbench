# messagetag

命令行认证标签工具，提供：

- `--version`：版本查询；
- `tag`：使用自己提供的密钥，对消息文件的完整内容计算 HMAC-SHA-256 认证标签。

## 依赖

- 支持 C++20 的编译器（CMake 构建中关闭了编译器扩展）；
- CMake 3.20 或更高版本；
- OpenSSL（使用其 `libcrypto` 中的标准 HMAC/SHA-256 实现，需 OpenSSL 1.1.1 及以上，OpenSSL 3.x 亦可）。

Debian/Ubuntu 上可通过 `sudo apt install libssl-dev` 安装开发文件。若 OpenSSL 不在标准搜索路径，可在配置时指定：

```sh
cmake -S . -B build -DOPENSSL_ROOT_DIR=/path/to/openssl/prefix
```

## 构建与运行

```sh
cmake -S . -B build
cmake --build build
./build/messagetag --version
```

输出版本号并以退出码 0 结束：

```text
messagetag 0.1.0
```

## 生成认证标签

```sh
messagetag tag --key-hex <十六进制密钥> --file <消息文件路径>
```

### 密钥的表示

- `--key-hex` 表达的是**原始密钥字节**：每两位十六进制字符对应一个字节，大小写字母均接受。
- 开头的零必须保留。例如 `0001` 表示两个字节 `00 01`，不会被当作数值 `1`，也不会把字符 `"0001"` 本身作为密钥。
- 密钥必须非空，且字符数为偶数，只接受数字与字母 `a-f`/`A-F`；不接受 `0x` 前缀，也不接受夹带的空白字符。
- 不符合以上规则时按参数错误处理，不会产生认证标签；错误信息也不会回显密钥内容。

### 消息文件按字节处理

- 消息取自文件中的**全部原始字节**，不作文本解释：不去掉末尾换行、不转换换行形式、不忽略零字节。
- 空文件是合法消息，仍会生成标准 HMAC-SHA-256 标签。
- 文件路径只用于定位输入，不参与认证：相同密钥、相同文件内容放在不同路径下会得到相同标签。

### 输出与退出码

成功时，标准输出只包含一行由 **64 个小写十六进制字符**组成的标签，以换行结束，退出码为 `0`，可以直接保存或交给其他程序处理：

```text
307a25cbcb6cbca48f5dd2b05fd9174c0cf17580f4ea8dd667092f11a77b4d5d
```

| 情况 | 标准错误 | 标准输出 | 退出码 |
| --- | --- | --- | --- |
| 成功 | 无 | 标签（一行） | `0` |
| 文件无法打开或读取失败 | 读取失败说明 | 无任何输出 | `1` |
| 缺少必需参数、密钥格式错误、存在不认识的参数 | 明确原因及该命令用法 | 无任何输出 | `2` |

## 示例

密钥为两个字节 `00 01`（写作 `0001`，前导零有意义），消息文件内容为 `hello` 加一个换行符，共 6 个字节：

```sh
printf 'hello\n' > msg.txt
./build/messagetag tag --key-hex 0001 --file msg.txt
```

输出：

```text
307a25cbcb6cbca48f5dd2b05fd9174c0cf17580f4ea8dd667092f11a77b4d5d
```

注意末尾换行属于消息的一部分；若文件内容是不带换行的 `hello`，得到的标签会不同。
